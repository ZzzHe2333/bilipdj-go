# BiliPDJ-Go 登录后自动启动（默认关闭）

> 这里的“开机自启”指 **当前用户登录系统后启动**，不是尚未登录时的系统服务。只有用户点击开关才会注册自启，安装、升级和第一次启动均不自动开启。

## 设置入口

1. 打开 Web 管理面板 http://127.0.0.1:9816/ → **平台与规则** → **开机自启**。
2. 默认显示 **已关闭**，勾选“登录系统后自动启动”即刻写入当前用户的系统登录启动项；取消勾选会移除。
3. Windows 可以在任务栏右下角（包含隐藏图标区域）右键点击 BiliPDJ-Go 托盘图标，选择 **开机自启（登录后启动）**。勾选表示已开启；再次点击取消。
4. Web 每次打开设置页、点击刷新、以及设置页打开期间每五秒读取一次操作系统的实际状态，与 Windows 托盘同步；不依赖浏览器本地缓存或 Go 队列存档。

**不会要求管理员权限，也不使用系统级开机服务。** Web 操作需通过现有管理 API 的本机同源校验或提供管理员 Token（POST/GET /api/autostart）。非本机访问需配置强随机 Token，不要将管理端口公开到公网。

## 各系统实现

| 系统 | 当前用户登录启动机制 | 限制 |
| --- | --- | --- |
| Windows 10 / 11 | 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `BiliPDJ-Go` 值 | 仅修改当前用户；指向当前可执行文件的绝对路径，并包含双引号；不需要管理员权限。 |
| Linux 桌面 | `$XDG_CONFIG_HOME/autostart/bilipdj-go.desktop`（默认 `~/.config/autostart/`） | 需支持 XDG Autostart 的桌面登录会话。无桌面的纯服务器应交给 systemd/user 服务管理。 |
| macOS | `~/Library/LaunchAgents/com.zzzhe2333.bilipdj-go.plist` | 在下次登录用户图形会话时运行。不是系统启动前的守护进程。 |
| Docker / Kubernetes | 不支持此开关 | 使用 `docker-compose.yml` 中的 `restart: unless-stopped` 或容器编排启动策略。 |

应用启动时只检查注册情况，不会偷偷写入；默认 **关闭**。无权修改启动项时，Web 返回错误并提示，Windows 托盘显示错误对话框。

### 更换安装目录

自启路径注册的是当前可执行文件的路径。将 EXE / 二进制**移动到其他目录后**，旧路径可能失效；请从新路径手动启动 BiliPDJ-Go，重新启用开机自启来刷新系统项。使用内置更新器直接替换同一路径下的 EXE 不需要改动自启设置。

### 启动参数

登录自启默认以当前可执行文件路径启动，**不附带自定义 `-listen`、`-data` 或 MCP 参数**。默认服务监听 `127.0.0.1:9816`，用户数据走 BiliPDJ-Go 正常的系统目录（不会跟 Python 版共用）。如果需要特殊监听端口或服务身份，请改用操作系统用户服务，并关闭本功能，避免重复启动或监听端口冲突。

### 卸载 / 清理

在卸载前关闭开关即可清理由本程序创建的启动项。卸载 EXE 本身不能保证操作系统自动清理登录启动项：Windows 可从任务管理器的“启动应用”管理，Linux/macOS 可手动移除上述文件。
