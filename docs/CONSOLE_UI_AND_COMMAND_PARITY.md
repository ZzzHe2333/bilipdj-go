# BiliPDJ-Go：排队交互、样式存档、权限与原版指令对照

## 当前 Web 使用方式

### 双击编辑、拖动排序

主控制台的「排队管理」和独立的 `/queue.html` 均支持**双击成员弹窗**，手动添加的条目可修改昵称、备注、手动来源标记；真正来自直播间的成员只允许编辑备注，不能伪造直播平台身份。点击「排序」进入拖放模式，可拖动行调整本地预览次序；点击**保存排序**后才写入当前排队存档。排序提交携带原始完整键顺序和当前存档号：若期间直播间新增成员、其他客户端改动排序或切换存档，后端返回 409，必须刷新重排。普通排序移动仍可用「上移/下移」。

### 浮窗实时预览与十个样式存档

「OBS 展示设置」的预览改为可拖拽浮窗，仍使用真实的 `/index` 透明展示 iframe 和原来的 `bilipdj:obs-preview-style` 实时消息；未保存时只影响此预览，不影响实际 OBS。浮窗可选择**样式 1–10**，支持**保存至槽位**、**读取预览**、**使用样式**（将已保存的槽位应用到实时 OBS）。当前生效样式继续保存在 `style-web.json` 与 Go 状态，10 个预设放在 `state.json` 内的 `style_slots`，与**排队存档 1–10 完全独立**。操作需要原管理权限，不会读取或写入 Python Tk 的 `style-win.json`。

### 权限表

原来的“管理员、最高管理员、舰长、黑名单”文本框替换为明确的**昵称（ID）/平台/身份/权限内容**表。仅显示显式添加或从旧权限名单转换过来的成员，**不会自动收集直播弹幕用户**。可选平台为 B站、抖音或两平台；同昵称可有两个独立平台身份，平台专属设置优先于“两平台”设置。

| 身份 | 管理能力 |
| --- | --- |
| 超级管理员 | 所有管理能力，包括通过弹幕任命/撤销管理员 |
| 管理员 | 默认可以拉黑/解黑、增删/完成排队、插队命令、切换排队开关和设置人数上限；**不能任命管理员**。上述五项能力可逐项关闭 |
| 兼职 | 只能使用明确勾选的管理命令，默认仅能操作队列 |
| 用户 | 普通用户，权限表中的显式身份标注；未配置者仍是普通用户 |
| 黑名单 | 不能使用排队和管理命令；管理员/超级管理员可用弹幕「拉黑 昵称」「取消拉黑 昵称」操作（仅本平台） |

**重要安全边界：** 用户明确选择使用昵称而非平台用户 ID；昵称在直播平台上未必唯一，不可将此当作已验证的强身份认证。B站主播身份仍按平台认证信息核实。旧版未迁移的名字列表会在 API 查询时呈现为“两平台”条目；首次保存结构化权限名单后该名单成为鉴权来源（包含显式空列表），以免重启时恢复旧管理员授权。管理员 Token 与直播内身份是两套独立的管理入口。

### 直播配置标签与自启位置

直播平台配置采用**浏览器式标签条**切换查看，主 B站/主抖音仍沿用旧 `config.bilibili`、`config.douyin`；额外直播间继续保存在 `config.listeners`。多房间使用现有 Go B站/抖音监听实现，多份独立 Cookie，无新增第三方直播 SDK。每个新增启用的 B站房间必须提供含 `SESSDATA` 的专属 Cookie；多 B站房间同时启用时主房间也必须提供 Cookie。为兼容旧状态，只有**单个旧主房间**仍可沿用旧版匿名监听行为。更多信息见 [多直播间说明](./MULTI_ROOM.md)。

开机自启从「平台与规则」移到新导航项 **「系统配置」**；Windows 右下角托盘开关仍可用，默认关闭。

## 与 Python 主仓库排队指令逐项对照

依据 [Python 主仓库 apps/server/server.py](https://github.com/ZzzHe2333/bilipdj/blob/main/apps/server/server.py) 中直播弹幕命令判定、[Go internal/core/commands.go](../internal/core/commands.go) 与随仓库的单元测试对照：

| 命令类别 | Python 旧版 | Go 当前实现 |
| --- | --- | --- |
| 普通排队 | `排队`、`排队 备注`，Go 支持配置关键词及冒号备注 | 支持；同平台同用户 ID 防重复 |
| 官服排 | `官服排`、`排官服`、`官服排队`、`排队官服`，支持部分空格备注 | 支持，对应 `Mode=官服` |
| B服排 | `B服排`、`b服排`、`排b服`、`排B服`、`B服排队`、`排队B服` 等 | 支持，对应 `Mode=B服` |
| 超级/米服 | `超级排`、`超级排队`、`小米排`、`排小米`、`排米服`、`米服排 备注` | 支持，分别对应超级/米服 |
| 自助取消/修改 | `取消排队`、`排队取消`、`我确认我取消排队`、`修改 备注`、`替换 备注` | 支持，受各自开关控制 |
| 管理队列 | `完成`、`完成 序号`、`删除 序号`、`del 序号`、`add/新增/添加 昵称` | 支持，受表格角色的「队列管理」能力限制 |
| 管理插队 | `无影插 位置 昵称` 限 1–20，`插队 位置 昵称` 限 1–30；超出当前人数则放队尾 | 已修正为 Python 同样上限与队尾位置裁剪，受「插队命令」权限限制 |
| 舰长插队 | 合规 B站舰长可发送 `插队`，须启用舰长开关 | 仅信任验证过的 B站舰长等级；独立于管理员命令插队 |
| 管理排队开关 | `暂停排队功能` / `恢复排队功能`、舰长与房管设置 | 支持，受「排队开关」权限限制 |
| 黑名单/管理员 | `拉黑 昵称`、`取消拉黑 昵称`、超级管理员用 `添加管理员 昵称` / `取消管理员 昵称` | 支持；现按消息所属平台新增/移除角色，防止跨平台同名越权 |
| 人数上限 | `设置排队人数...` 或 `设置排队上限...`，Python 实现未固定 10000 上限 | Go 继续保留 **1–10000** 的安全限制，故不是任意大的数值完全等同 |

**其余差异：** 原版 Python 将服类别编码进昵称文本（如 `官|用户名`），Go 在存档内部使用结构化 `mode`；OBS 默认只显示用户名。Go 不执行 Python 专属插件命令，且多平台的同名授权由新表分别处理。这不是宣称 Python 和 Go 的全部内部处理分支完全一致；已对用户列出的常用指令及新增管理员权限行为加入自动化测试。

## 验收范围

CI 检查 `go test ./...`、`go vet ./...`、`go test -race ./...`、前端 JS 语法以及 Windows/Linux/macOS 的 AMD64/ARM64 交叉编译。CI 不能模拟触控设备真实拖拽、真实 B站/抖音连接或浏览器窗口拖动的用户体验，仍需要真机最终验收。本次仅合并源代码，不创建发行版。
