# 队列存档与配置保存原子性修复（2026-10-11）

## 本次范围

1. **队列档位保护**：`POST /api/queue` 的 add/insert/edit/remove/move/clear/reorder 全部必须提交 `slot`（整数 1–10），与服务器当前存档不一致返回 **409 Conflict**，缺失或无效返回 **400**。这是必须由服务端检查的防误操作措施，旧无 `slot` 写入请求必须升级。
2. **队列保存失败回滚**：操作前复制当前队列和完整槽位映射。任何存档保存失败，均恢复队列和槽位的内存状态；如果 Windows Local 目录使用独立的 `go-queue-state.json`，则还会重新写入旧存档，防止 Roaming `state.json` 失败后 Local 队列内容已改变。二次回滚失败时返回明确错误，不报告操作成功。
3. **队列槽位切换失败回滚**：`POST /api/queue/slots` 保存失败后，恢复原来的活动槽位、队列和其他槽位；不会广播切槽成功。
4. **普通配置回滚**：`POST /api/config` 先暂存旧配置，只有 `saveLocked()` 成功后才生效并重启直播监听；失败返回 500 并恢复原内存配置，不虚报成功。
5. **监听重启串行化**：更改配置和重新应用监听现在位于同一 `a.mu` 独占锁持有期内，防止旧 HTTP 请求在新 HTTP 请求之后重建旧直播间监听任务。扫码登录/退出仍只会定向重启对应房间。
6. **管理员读取权限**：`GET /api/config` 现在和保存一样，必须有当前主机的可信本机访问权限或有效 `X-Admin-Token`。不再向能连接服务的未授权远程设备返回管理员名单、黑名单和房间状态。Cookie 明文仍完全屏蔽。

## 前端和工具兼容

主 Web、独立 `/queue.html` 的所有队列修改请求均传当前所见槽位；独立排队页编辑弹窗传打开时的槽位。内置 MCP 工具为了保持已有工具输入参数兼容，每次写操作会先查询服务器的活动存档，再将该档位和操作一起提交；若查询与提交之间发生切槽，后端会返回 409 而不误操作。

外部自行开发的 HTTP 客户端也必须升级：每次队列写入前读取 `GET /api/queue/slots`，将 `active_slot` 作为请求的 `slot` 参数提交。请勿遇到 409 时自动强制重复写入，应该先展示给用户并要求确认新的槽位。

## 自动化测试与限制

`internal/core/queue_transaction_test.go` 覆盖普通配置失败回滚、切槽失败回滚、全部队列动作缺失/错误目标档拒绝、所有队列动作写入失败回滚、远程配置接口鉴权、并发配置保存后运行实例状态、Local 独立队列文件失败恢复。保留原有 MCP 工具写入测试和权限与 OBS 样式存档测试。

**限制：** 常规文件写入失败支持回滚；发生进程被强制杀死、突然断电、硬盘永久失效时仍无法实现跨两个独立物理文件的真正原子性，需要用户备份。未在真实账号与 Windows 浏览器中进行人工端到端点击验收。本次只修改仓库代码，不发布安装包。
