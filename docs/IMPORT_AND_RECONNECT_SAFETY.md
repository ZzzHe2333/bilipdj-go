# Python CSV 导入与多直播间重连安全修复

## Python CSV 归档导入

- 对 `POST /api/storage/python-queues/import` 建立当前槽位、队列和全部 10 个存档槽位的状态快照。
- 写入 CSV 导入结果时，Go 会先保存独立的 Local 队列文件，然后提交 Roaming 中的 `state.json`。若第二步失败，必须通过 `restoreQueueLocked` 恢复内存、所有存档槽位及 Local 文件，而非只替换内存字段。
- 如果恢复 Local 文件也失败，接口明确返回两项失败信息，不能宣称恢复成功；失败的导入不会发布成功的队列更新事件。
- 源 Python CSV 仍为只读，成功和失败都不修改源文件。

## 单直播间重连

- 每个直播间都有独立可取消的监听上下文。在凭据重新登录、注销或定向重连时，前一监听上下文被取消。
- 之前弹幕回调只在获得应用锁之前检查是否被取消，可能在检查与写入之间被定向重连；状态回调只检查全局监听代数，无法充分隔离同一房间的定向重连。
- 现在弹幕、礼物回调会**在 App 独占锁内**同时检查上下文是否仍有效及全局监听代数，随后才处理队列或礼物积分。状态回调也在同一锁内检查上下文有效性；过期连接不能把旧连接状态覆盖到刚重连的房间。
- 其他直播间不用因为单房间刷新而中断。

## 验收与限制

- `internal/core/reconnect_import_safety_test.go` 添加故障注入和可控重连回调测试，检查内存、Roaming、Local 及旧连接状态。
- CI 要运行 Go 全量单测、静态检查、竞态检测、前端 JS 语法和六平台交叉编译。
- 正常磁盘写入错误可以回滚；设备断电、永久磁盘故障或再次回滚失败不能保证双独立文件的强事务。未进行真实 B站/抖音账号及 Windows GUI 实机端到端验证。
- 未改变程序版本号或创建 GitHub Release。
