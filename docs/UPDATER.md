# BiliPDJ Go 应用内自更新（v0.10.0）

## Windows 使用方法

1. 在 Web 控制台打开「软件更新」。
2. 选择「自动（官方优先）」「GitHub 官方」或「第三方 GH-Proxy」。
3. 点击检查更新；有新版本时点击「下载并验证 SHA-256」。
4. 确认版本号、目标系统架构，点击「安装更新并重启」，确认弹窗。
5. 托盘进程退出后，独立更新助手替换程序并启动新版本；关闭的浏览器控制台会由新版重新打开。

**注意**：更新会短暂中断直播弹幕监听和队列服务，不会修改已有 `state.json` 或 Python 兼容 CSV。请先备份数据，并停止其他同名程序实例。应用需对程序 EXE 所在文件夹有写权限；安装在 Program Files 等受保护路径时请先转移到用户可写目录，或由管理员进行维护。

## 文件与回滚

- 下载文件存放在当前 Go 用户数据目录的 `updates/`，先核验 ZIP 完整大小和 SHA-256。
- ZIP 只提取与当前系统对应的 `bilipdj-go.exe` / `bilipdj-go`；不信任 ZIP 目录结构，不将其他文件覆盖到应用目录。
- 另行启动临时更新助手，旧主程序退出后才替换程序文件。
- 原二进制保留为同目录的 `bilipdj-go.exe.backup-<版本>`（其他系统无 `.exe`）；如新版无法启动或未通过 `/health` 版本检查，尝试恢复旧版。
- 配置与队列不会删除或重建。Docker 原生镜像不能通过此功能修改容器内部可执行文件，必须使用 `docker compose up -d --build` 等镜像升级方案。

## 官方与加速线路

- **自动**：先试 `api.github.com` 的 Release 元数据；不可访问时，改用第三方代理获取该版本的 `update-manifest.json`，其中包含六平台更新包大小和 SHA-256。ZIP/校验文件下载时，官方失败自动切换代理。
- **官方直连**：不使用第三方代理，仅使用 GitHub Release 接口及附件。
- **第三方加速**：优先使用 `https://gh-proxy.com/`，失败尝试 `https://gh-proxy.org/`，均失败再试官方 GitHub；两个域名均是第三方，非 Bilibili / GitHub / BiliPDJ 官方服务。
- 所有 URL 固定到项目 `ZzzHe2333/bilipdj-go` 的 Release 附件，不接受用户提供的任意下载链接，也不自动降级版本。

**重要的完整性边界**：SHA-256 能防止 ZIP 与校验文件内容不一致、网络中断与缓存损坏。**若第三方代理同时篡改更新清单与 ZIP，单靠 SHA-256 不能认证发行者**。在安全优先的环境，请使用 GitHub 官方直连，并自行对照官方发布的校验值；不要将加速代理当作可信签名机构。目前版本未提供独立的发布签名验证。

## 故障处理

- 更新检查超时：手动选择「第三方加速」；代理服务也可能暂时不可达，届时需更换网络或手动下载安装包。
- 无法替换程序：检查安装目录权限、是否另有实例占用文件，并在必要时从旧版备份恢复。
- 安装时提示本地状态不可用：先点击下载并校验，再点击安装；安装接口不会接受浏览器传入任意本地程序路径。
- Linux/macOS 的进程重启不等同于 `systemd` 服务重启；如由服务管理器托管，建议使用服务部署流程更新，确保重启策略一致。
