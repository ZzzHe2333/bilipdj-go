# 2026-10-11 权限 / 排队存档 / OBS 一致性修复

## 修复内容

- **权限与平台配置独立写入**：`POST /api/config` 只负责直播平台和普通设置，不再修改 `permissions`、`admins`、`super_admins`、`guards`、`blacklist`。角色/黑名单只能通过 `POST /api/permissions`（或已经授权的弹幕管理命令）更新。这个约束由后端执行，防止其他浏览器标签页的过期表单覆盖新权限。旧客户端继续可以读配置，但提交过时的角色字段不会生效。
- **排队存档切换独立**：`POST /api/config` 携带的 `archive_slot` 被忽略，取当下已经生效的槽位。切换存档必须使用 `POST /api/queue/slots`。避免多页面配置保存时意外把队列切回旧档。
- **封禁优先**：对于同名同平台，`all` 黑名单或该平台黑名单优先于管理员、超级管理员、兼职、普通用户身份；B站身份不能绕开双平台封禁。
- **旧 UserID 黑名单**：过去存储在旧 `blacklist` 名单中的用户 ID 继续匹配当前弹幕的 `user_id`，即使系统已经保存了结构化身份表，也不能静默放行。
- **取消拉黑隔离**：弹幕“取消拉黑 昵称”只能移除操作所在平台的黑名单项，不得顺带删除跨平台 `all` 项。若需要解除双平台封禁，可到权限表手动编辑/删除 `all` 条目。
- **旧封禁清理**：从权限列表删除通过旧名单迁移过来的封禁时，后端同步清理该旧名单条目，防止旧 UserID 继续生效造成“解除黑名单没有作用”。
- **OBS 双文件一致性**：普通样式保存和样式槽位应用都先保存 `state.json`，再写 `style-web.json`（或 `appearance-web.json`）。第二步失败时恢复旧内存状态并重新保存原状态；两步全成功后才通过事件推送新样式。如回滚也失败，接口会明确报告这两次写入失败，不能假装保存成功。

## 数据兼容及限制

- 不修改 `VERSION`，不迁移或清空旧排队存档。
- 历史黑名单既可能包含昵称也可能包含纯用户 ID；由于旧格式没有保存每个 ID 的平台归属，旧 ID 封禁的保守兼容逻辑可能在不同平台出现相同用户 ID 时同时拦截。管理员可以在新权限表移除旧封禁并重新为指定平台添加正确条目。
- 当前 OBS 操作对**正常返回的磁盘写入错误**提供回滚；进程被突然终止、磁盘断电及文件系统本身失效时不能保证跨两个不同文件的强事务性。此类环境仍需要备份。
- 系统原有的管理员 Token 与同源校验不变。浏览器前端、跨平台直播间、托盘自启的其它功能不受本次变更影响。

## 回归测试

`internal/core/fix_regression_test.go` 覆盖 all 封禁优先、历史 UserID 黑名单、平台专属取消拉黑、迁移后解除封禁、跨页面保存过期权限/槽位、普通及槽位 OBS 写入失败回滚。发布包未更新，代码需在下一次明确的版本发布后才会出现在用户正式下载的安装包。
